# سجل قرارات التنفيذ

## ADR-001 — محاكاة أولًا، 3 أكتوبر 2026

قرار صاحب المشروع: نبدأ على الكمبيوتر، والهدف عرض في 8 أكتوبر. لا تغييرات على شبكة المضيف، ولا مزود AI مدفوع. كل نتيجة mock موسومة. هذا لا يلغي متطلبات المختبر الحقيقي من المخطط.

## ADR-002 — زيادة رأسية محلية قبل توزيع الخدمات

لإتاحة رحلة تعمل مبكرًا، الإصدار 0.1 يستخدم Python/FastAPI بعملية واحدة وSQLite للمعاملات على aggregate التجربة، وReact/TypeScript. هذا خروج مؤقت ومعلن عن PostgreSQL/outbox والخدمات المنفصلة في الدليل. لا نضع ملفات فارغة توحي بأن تلك الوحدات منجزة. البطاقات 008–013 تعيد التنفيذ إلى المخطط. الهوية الحالية operator/viewer محلية وليست توزيع أدوار مؤسسيًا.

## ADR-003 — استقلال التحقق منطقيًا

planner يستخدم بحث الوصول؛ validator يبني transitive closure ولا يستورد planner. تتشارك الوحدتان الـschemas فقط. الخطة وsnapshot لهما hashes يعاد فحصهما قبل التطبيق. الخدمة المستقلة واختبارات الشبكة لاحقًا.

## ADR-004 — أدلة قابلة للفحص دون ادعاء ميداني

مثال 16 مجموعة قابل للحساب، والبيانات في الشاشة اصطناعية. لا يُعاد استخدام أرقام الملصق أو الدليل كأنها نتائج شبكة فعلية. benchmark شامل لم ينفذ. تُسجل الأخطاء والحالات غير المحسومة دون إسقاطها من التقرير.

## ADR-005 — vault داخل Git هو مرجع الفريق

Markdown وروابط نسبية؛ قابل للقراءة في GitHub وObsidian دون خدمة إضافية. كل PR يحدّث الحالة والتسليم. المجلد ليس بديلًا عن مراجعة الكود أو CI، ولا يحدّث الفروع القديمة تلقائيًا؛ على العضو سحب main قبل البداية.

## ADR-006 — حدود الإصدار الحالي

lineage مثبت في fixture، والتأخير نموذج لنتيجة معلّقة بmanifest، واستعادة المحتوى حتمية. فحص الإفصاح حقول منع محددة بالعربية والإنجليزية. لا ادعاء بتعميم التصنيف أو جودة الاستعادة على بيانات حقيقية. العام هنا مصدر GitHub فقط؛ الاستضافة العامة تحتاج قرار نشر منفصل.
