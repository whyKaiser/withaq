# مراحل المشروع وبوابات الخروج

المراحل تصف القدرات؛ Sprints تحدد نافذة تسليم الفريق. تحديث 3 أكتوبر: التنفيذ التقني تقدّم على التواريخ المخططة؛ المراجعة البشرية وتشغيل عضو آخر لم يحدثا بعد.

| المرحلة | بوابة القبول | حالة الإصدار 0.2 |
|---|---|---|
| P0 — السياق والبيئة | المصدر والlocks والمigrations والهوية المحلية | يعمل؛ CI وتشغيل عضو ثانٍ متبقيان |
| P1 — القرارات | oracle، empty/timeout، تحقق مستقل ورفض tampering | متحقق في النموذج وخدمة validator مستقلة |
| P2 — سلطة البيانات | PostgreSQL، lineage، barriers، outbox/fencing | متحقق ببيانات اصطناعية، races وعامل قُتل وأعيد تشغيله |
| P3 — الإفصاح والتكامل | exact bytes، approval، admission، unknown outcomes، console | يعمل بمزود mock؛ منع الخروج الشبكي المؤسسي متبقٍ |
| P4 — شبكة المختبر | denies قبل established acceptance، كل وظيفة مقاسة | تجربة G/X/P/M/A معزولة ناجحة؛ ليست PEP دائمًا أو أجهزة مادية |
| P5 — التأهيل والعرض | raw results، restore، reproduction، review | 300 إعداد model-only واستعادة PostgreSQL منفذان؛ مراجعة مستقلة متبقية |

هدف 8 أكتوبر: عرض مختبر قوي قابل لإعادة التشغيل وأدلة صريحة. لا يعني اكتمال كل أبواب النظام الإنتاجي في الدليل.
